Make `satellite-connection` a plugin-backed reactive entity backed by the DURABLE, globally-readable `satellites` table via the Model-B entity state machine.

Satellite defines a `satellite-connection` entity `{ status: "online" | "offline", name, region, lastSeenAt, lastEvent }` keyed by satellite id. Its current state is PLUGIN-BACKED by durable columns on the shared `satellites` table - `connection_status` (default "offline"), `last_seen_at`, and `last_connection_event` - so it is readable from ANY pod; there is no `entity_state` mirror. `defineEntity({ kind: "satellite-connection", read })` reads those columns via `SatelliteService.getManyConnectionStates`. The three lifecycle sites - WS authentication (online/connected), WS socket close (offline/disconnected), and the heartbeat monitor's online->offline edge (offline/heartbeat_lost) - drive `handle.mutate({ id: satelliteId, apply })`, where `apply` UPDATEs the satellite row's connection columns (the pod that owns the socket is the writer) and returns the view. The platform still records full transition HISTORY in `entity_transitions` for every change. The `satellites.last_heartbeat_at` column stays escape-hatched bookkeeping (`declareNonReactiveState`, reason "bookkeeping").

This fixes a horizontal-scaling read bug: connection state previously lived in a process-local in-memory map, so a satellite connected to pod A was invisible to pod B's reads (scope enrichment / `wait_until` re-eval can run on any pod). The state is now durable and globally consistent. The heartbeat-timeout monitor remains the offline-on-timeout backstop: a pod that dies without flipping its satellites to offline leaves a stale "online" only until the monitor observes the timeout and writes "offline" - this change does not attempt full distributed presence, only correctness where pod-local memory was wrong.

A registered change-deriver maps these entity changes back to the `satellite.connected` / `satellite.disconnected` / `satellite.heartbeat_lost` trigger events, so existing automations keep firing. The three-way distinction is preserved by an explicit `lastEvent` discriminator on the entity state: a bare `status` diff cannot tell a socket drop (`disconnected`) apart from the heartbeat-lost offline edge (`heartbeat_lost`), so the deriver reads `lastEvent` to fire the exact original event. The old connection hooks are removed in favor of the reactive entity.

BREAKING CHANGES:
- New `satellites` columns `connection_status` / `last_seen_at` / `last_connection_event` are added by migration `0001_tiresome_terror.sql`. Existing rows backfill to `connection_status = 'offline'` with null `last_seen_at` / `last_connection_event` (treated as never-connected until the next lifecycle edge), so the entity reports no current state for them until they next connect.
- Removed the `satellite.connected`, `satellite.disconnected`, and `satellite.heartbeat_lost` hooks (`createHook`). Use the `satellite-connection` entity's auto-emitted change events (subscribe via the `automation.entity` extension point's `onEntityChanged`, or author automations against the derived trigger events). The `satellite.removed` deletion/cleanup hook is unaffected and stays.
- Removed the hook-backed `connected` / `disconnected` / `heartbeat_lost` automation triggers. The same qualified trigger event ids are now produced by the entity change-deriver, so already-authored automations referencing them continue to fire, but they are no longer offered as picker entries in the automation editor. The trigger payload is now the entity-change shape (`kind`, `id`, `prev`, `next`, `delta`, `changedFields`, plus the new state fields spread at top level: `status`, `name`, `region`, `lastSeenAt`, `lastEvent`) rather than the old hook payload (`satelliteId`, `name`, `region`, `timestamp`).
- The `satellite-connection` entity's current state is the durable `satellites` connection columns, NOT a framework `entity_state` row. Any code reading current connection state must read through the entity `read` accessor / `handle.get`. Durable history in `entity_transitions` is unaffected.
